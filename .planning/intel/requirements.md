# Requirements Intel

Synthesized from PRDs. Each requirement has a stable ID, source provenance, description, and acceptance criteria.
Mapping: 4 core features (REQ-feat-*) + 5 execution phases (REQ-phase-*).

---

## REQ-feat-fastapi-backend-wrapper

- **Source:** docs/MIGRATION-SPEC.md § "Feature 1 — Python FastAPI Backend Wrapper"
- **Scope:** Python repo / financial backend
- **Description:** Wrap the legacy 4-stage ML pipeline in a FastAPI server that exposes the financial brain as HTTP endpoints consumable by the Next.js orchestrator.
- **Acceptance criteria:**
  - `POST /api/recommend` accepts the 12 investor profile fields and returns an asset-weight allocation (e.g., JSON allocation map of tickers → weights summing to 1.0).
  - `POST /api/current-prices` accepts a list of tickers and returns live yfinance market prices for dashboard valuation.
  - Endpoints live in the existing Python origin repo (alongside `src/`, `pipeline.py`, etc.) — not in the frontend repo.
  - Real-time ETF price fetching remains in Python (not delegated to Next.js).

## REQ-feat-onboarding-form

- **Source:** docs/MIGRATION-SPEC.md § "Feature 2 — Shadcn Multi-Step Investor Onboarding Form"
- **Scope:** Next.js frontend
- **Description:** Build a premium multi-step onboarding form that captures the 12 frozen investor profile fields.
- **Acceptance criteria:**
  - Form is multi-step (not a single long page).
  - Uses Shadcn/ui components.
  - All 12 fields from `DEC-investor-profile-schema-frozen` are collected with correct types and enum constraints enforced.
  - Client-side validation uses Zod schemas.
  - On submit, profile is persisted to Supabase `profiles`/`portfolios` and a baseline portfolio is generated by calling `POST /api/recommend`.

## REQ-feat-realtime-dashboard

- **Source:** docs/MIGRATION-SPEC.md § "Feature 3 — Real-Time Financial Dashboard"
- **Scope:** Next.js frontend + Python FastAPI
- **Description:** Render the user's active allocation with charts and live valuation.
- **Acceptance criteria:**
  - Displays the active asset allocation via donut/pie chart (e.g., Recharts/Tremor).
  - Queries `POST /api/current-prices` for live prices to compute aggregate current asset value.
  - Displays Recharts-driven performance timeline backed by `portfolio_history`.
  - Surfaces ROI highlights.
  - Tracks/visualises the split between the frozen `ml_result` baseline and the live `current_allocation` (per `DEC-state-isolation-baseline-vs-current`).

## REQ-feat-conversational-finetuning-drawer

- **Source:** docs/MIGRATION-SPEC.md § "Feature 4 — Conversational Fine-Tuning Drawer"
- **Scope:** Next.js frontend (Vercel AI SDK)
- **Description:** A slide-out (or split-screen) chat UI that lets the user tweak their allocation conversationally.
- **Acceptance criteria:**
  - UI is a slide-out drawer or split-screen chat surface.
  - Built on the Vercel AI SDK.
  - Wires up the two tool handlers — `adjust_allocation` and `update_investor_profile` — per `DEC-llm-tools-exactly-two`.
  - Tool execution mutates the active chart state instantly in the current view.
  - Chat sequence persists to Supabase `chat_messages`.
  - When `current_allocation` diverges from `ml_result`, the comparative banner copy from `DEC-state-isolation-baseline-vs-current` is shown.

## REQ-phase-2-database-init

- **Source:** docs/MIGRATION-SPEC.md § "Execution Plan / Phase 2"
- **Scope:** Supabase
- **Description:** Produce a PostgreSQL initialization script for Supabase that creates all tables, types, and constraints.
- **Acceptance criteria:**
  - A single SQL migration file is produced for the Supabase SQL Editor.
  - The file creates the 4 tables defined in `DEC-db-tables-fixed`: `profiles`, `portfolios`, `portfolio_history`, `chat_messages`.
  - `profiles` is linked to `auth.users`.
  - `portfolios` stores the 12 input features AND the `allocated_assets` JSONB allocation map.
  - All enum types and column constraints reflect `DEC-investor-profile-schema-frozen`.

## REQ-phase-5-llm-chat-integration

- **Source:** docs/MIGRATION-SPEC.md § "Execution Plan / Phase 5"
- **Scope:** Next.js frontend + Supabase
- **Description:** Wire up the Vercel AI SDK chat agent to execute the two tool handlers that mutate frontend chart state and save records to Supabase.
- **Acceptance criteria:**
  - Vercel AI SDK chat surface present on the dashboard (per `REQ-feat-conversational-finetuning-drawer`).
  - `adjust_allocation` handler applies signed deltas to `current_allocation` and renormalizes to 1.0; tickers unchanged.
  - `update_investor_profile` handler re-calls `POST /api/recommend` with merged 12-field payload, wipes qualitative overrides, and resets the baseline.
  - Both tools persist outcomes to Supabase (`chat_messages`, and `portfolios`/`portfolio_history` as appropriate).

## Component Responsibilities

| Component | Responsibility | File |
|-----------|----------------|------|
| ETF Fetcher | Fetches 95 ETF records from yfinance + Finnhub APIs, saves raw CSV | `src/etf_fetcher.py` |
| Morningstar Rater | Computes Sharpe-based composite star ratings per ETF category | `src/morning_star_rating.py` |
| Data Generator | Synthesises 5,000 investor profiles with correlated, balanced features | `src/data_generation.py` |
| Data Validator | Cleans and validates ETF and investor dataframes; produces markdown reports | `src/data_validation.py` |
| Validation Rules | Single-source-of-truth for allowed field values and numeric ranges (shared by training and inference) | `src/validation_rules.py` |
| Prepare Data | Runs label-generating allocation pipeline, engineers 19 features, splits train/test, saves CSV + preprocessor | `src/prepare_data.py` |
| Allocations | Rule-based label generator AND inference Stage 4: AUM-weighted ETF selection with conflict resolution | `src/allocations.py` |
| Train Models | Trains 5 classifiers (Stage 1), 2 multi-output regressors (Stage 2), 1 RF regressor (Stage 3); saves winners as .pkl | `src/train_models.py` |
| Inference Engine | Loads artifacts once (cached), validates input, runs all 4 stages, returns recommendation dict | `src/inference.py` |
| LLM Layer | Wraps OpenAI gpt-4o-mini; provides initial explanation and tool-calling chat for portfolio adjustments | `src/llm.py` |
| Pipeline Orchestrator | Coordinates training pipeline steps 1-4 with skip flags and caching checks | `pipeline.py` |
| Web App | Streamlit UI: form submission, portfolio display, Plotly chart, LLM chat interface | `app.py` |

## Pattern Overview

**Overall:** Multi-stage sequential ML pipeline (train path) + cached model loading (inference path), with a rule-based Stage 4 shared across both paths.

**Key Characteristics:**
- Training and inference share `src/allocations.py` — Stage 4 rule logic is not duplicated
- All ML models are persisted to `models/*.pkl` via joblib; loaded once at module level in inference
- Labels for ML training are generated by the same rule-based allocations logic that runs at inference time (circular label generation — this is a known architectural constraint, see CONCERNS.md)
- LLM layer is a thin overlay that can adjust allocation weights or re-trigger the full ML pipeline; it does not replace the ML stages
- Input validation is shared between the training data validator (`src/data_validation.py`) and live inference (`src/inference.py`) via `src/validation_rules.py`

## Layers

**Data Acquisition Layer:**
- Purpose: Pull and persist raw ETF metrics from external APIs
- Location: `src/etf_fetcher.py`, `src/morning_star_rating.py`
- Contains: yfinance + Finnhub API wrappers, Sharpe-style rating computation
- Depends on: yfinance, finnhub, dotenv (FINNHUB_API_KEY from `.env`)
- Used by: `pipeline.py` step 1 and 1.5

**Data Engineering Layer:**
- Purpose: Synthesise investors, validate inputs, run rule-based allocation to produce ground-truth labels, feature-engineer and split data
- Location: `src/data_generation.py`, `src/data_validation.py`, `src/validation_rules.py`, `src/prepare_data.py`, `src/allocations.py`
- Contains: Synthetic data generation with correlated features, validation report generation, sklearn ColumnTransformer (StandardScaler + OneHotEncoder), 80/20 stratified split
- Depends on: pandas, numpy, sklearn, `src/allocations.py`
- Used by: `pipeline.py` steps 2 and 3

**Model Training Layer:**
- Purpose: Compare algorithms per stage, select winner by macro F1 / MAE, persist models and metrics
- Location: `src/train_models.py`
- Contains: KNN, Logistic Regression, Random Forest (GridSearchCV), XGBoost, MLP for Stage 1; MultiOutputRegressor with RF and GradientBoosting for Stage 2; RF for Stage 3
- Depends on: sklearn, xgboost, joblib, `data/training/*.csv`
- Outputs: `models/risk_profile_classifier.pkl`, `models/allocation_regressor.pkl`, `models/etf_count_regressor.pkl`, `models/risk_profile_rf.pkl`, `models/label_map.json`, `evaluation_reports/*.png`, `evaluation_reports/model_metrics.json`
- Used by: `pipeline.py` step 4

**Inference Layer:**
- Purpose: Accept a structured investor dict, validate it, run all 4 stages, return recommendation dict
- Location: `src/inference.py`
- Contains: `_load_artifacts()` called once at module level (lazy via `_get_artifacts()`), `validate_input()`, `recommend()`, `print_recommendation()`
- Depends on: `models/*.pkl`, `models/label_map.json`, `data/training/preprocessor.pkl`, `data/raw/combined_etf_with_morning_star.csv`, `src/allocations.py`, `src/validation_rules.py`
- Used by: `app.py`, direct CLI execution

**LLM Advisory Layer:**
- Purpose: Natural-language explanation and refinement of ML-generated portfolios via OpenAI function calling
- Location: `src/llm.py`
- Contains: `get_initial_explanation()`, `chat()`, `get_tool_followup()`, `apply_adjust_allocation()`, two tool schemas (`adjust_allocation`, `update_investor_profile`)
- Depends on: openai (gpt-4o-mini), OPENAI_API_KEY from `.env`
- Used by: `app.py`

**Presentation Layer:**
- Purpose: Streamlit web UI — investor form, portfolio visualisation, LLM chat
- Location: `app.py`
- Contains: Streamlit form, Plotly pie chart, session state management, tool dispatch loop
- Depends on: streamlit, plotly, `src/inference.py`, `src/llm.py`
- Used by: end users

## Data Flow

### Training Path (run once to produce model artifacts)

1. **ETF data fetch** — `src/etf_fetcher.py` → `data/raw/combined_etf_data.csv`
2. **Star rating** — `src/morning_star_rating.py` reads raw CSV, adds `custom_star_rating` → `data/raw/combined_etf_with_morning_star.csv`
3. **Investor generation** — `src/data_generation.py` creates 5,000 rows with 12 features → `data/processed/synthetic_investor_data_<ts>.csv`
4. **Data validation** — `src/prepare_data.py` calls `src/data_validation.py` → drops malformed rows, imputes ETF metrics, writes `data/validation_reports/<ts>.md`
5. **Label generation** — `src/prepare_data.py` calls `allocations.run_allocations_pipeline()` → attaches `risk_profile`, `allocation`, `num_*_etfs`, `total_etfs` to investor rows
6. **Feature engineering** — ColumnTransformer scales 6 numerics + one-hot encodes 6 categoricals → 19 features; preprocessor saved as `data/training/preprocessor.pkl`
7. **Train/test split** — 80/20 stratified on `risk_profile`; X and y CSVs saved to `data/training/`
8. **Model training** — `src/train_models.py` trains all candidates, selects winners → `models/*.pkl`, `models/label_map.json`, `evaluation_reports/*`

### Inference Path (runs per recommendation request)

1. **Input dict** received by `recommend(user: dict)` in `src/inference.py` (`src/inference.py:139`)
2. **Input validation** — `validate_input()` checks required fields, valid categorical values, numeric ranges (`src/inference.py:118`)
3. **Artifact load** — `_get_artifacts()` returns cached (preprocessor, classifier, alloc_regressor, count_regressor, label_info, etf_by_class); loads from disk only on first call (`src/inference.py:108`)
4. **Preprocessing** — `preprocessor.transform(X_raw)` → same 19-feature vector used during training (`src/inference.py:166`)
5. **Stage 1** — `classifier.predict(X_processed)` → `risk_profile` string (`src/inference.py:172`); XGBoost/MLP integer predictions decoded via `label_map.json`
6. **Stage 2** — `alloc_regressor.predict(X_processed)` → `equity_pct`, `bond_pct`; risk-profile-aware bounds clamped, `alt_pct` derived as remainder (`src/inference.py:181`)
7. **Stage 3** — `count_regressor.predict(X_processed)` → `total_etfs` integer clipped to [7, 13]; per-class counts from `get_num_etfs()` in `src/allocations.py` (`src/inference.py:208`)
8. **Stage 4** — `assign_portfolio_numeric_aum(investor_row, etf_by_class)` selects tickers iteratively with AUM-weighted sampling and CONFLICT_GROUPS exclusion (`src/allocations.py:173`)
9. **Return dict** with keys `risk_profile`, `allocation`, `total_etfs`, `etf_counts`, `portfolio`

### LLM Adjustment Path (post-recommendation, interactive)

1. `app.py` calls `get_initial_explanation()` once after form submit → LLM explains portfolio (`src/llm.py:142`)
2. On each chat turn, `chat()` is called with full chat history; returns either plain text or a tool call dict (`src/llm.py:164`)
3. If `adjust_allocation` tool: `apply_adjust_allocation()` applies signed deltas and renormalises in-place — ML pipeline is NOT re-run (`src/llm.py:249`)
4. If `update_investor_profile` tool: `app.py` calls `recommend()` again with updated inputs — full ML pipeline re-runs (`app.py:285`)
5. `get_tool_followup()` called to generate natural-language explanation of the change (`src/llm.py:223`)

**State Management:**
- All session state lives in `st.session_state` in `app.py` — no server-side persistence
- `_ARTIFACTS` module-level global in `src/inference.py` caches loaded models across Streamlit rerenders

## Key Abstractions

**`recommend(user: dict) -> dict`:**
- Purpose: Single public API for the entire 4-stage inference pipeline
- Location: `src/inference.py:139`
- Pattern: Validates input, transforms via cached preprocessor, runs 3 ML stages + 1 rule stage, returns structured dict

**`run_allocations_pipeline(etf_df, investors_df) -> DataFrame`:**
- Purpose: Batch label generator used exclusively during training data preparation
- Location: `src/allocations.py:250`
- Pattern: Applies probabilistic profile assignment, stochastic allocation, ETF count sampling, and portfolio assignment across all investor rows

**`assign_portfolio_numeric_aum(investor_row, etf_by_class) -> dict`:**
- Purpose: Shared Stage 4 logic — selects conflict-free ETF tickers per asset class
- Location: `src/allocations.py:173`
- Pattern: Per-class iterative pick using AUM-power × quality weights; removes picked symbol and CONFLICT_GROUP siblings from candidate pool after each pick

**CONFLICT_GROUPS:**
- Purpose: Prevents duplicate-fund portfolios (e.g., both VOO and SPY)
- Location: `src/allocations.py:11`
- Pattern: 8 predefined groups; "pick one, ban siblings" enforced by removing from candidate DataFrame

**`ValidationReport` dataclass:**
- Purpose: Human-readable validation result persisted as markdown to `data/validation_reports/`
- Location: `src/data_validation.py:26`
- Pattern: Shared by ETF and investor validation; surfaced in `prepare_data.py` output

**`label_map.json`:**
- Purpose: Records winning algorithm name and integer-to-label mapping for XGBoost/MLP predictions
- Location: `models/label_map.json`
- Pattern: Written by `src/train_models.py:296`; read by `src/inference.py:169`

## Architectural Constraints

- **Global state:** `_ARTIFACTS` module-level singleton in `src/inference.py:106` caches all model artifacts after first call; safe for Streamlit single-process server but not thread-safe across multiple workers
- **Label circularity:** Training labels are produced by the same stochastic `run_allocations_pipeline()` logic used at inference time. The `np.random.choice` calls in `allocations.py:116-123` introduce irreducible label noise that caps Stage 1 classifier accuracy around 46% (vs. 33% random baseline)
- **Stage 4 stochasticity:** `assign_portfolio_numeric_aum()` uses `np.random.choice` — the same investor profile produces a different ETF selection on each call
- **No inference pipeline for notebooks:** The notebooks in `notebooks/` shadow `models/` and `evaluation_reports/` as subdirectories — these are separate from the project-root `models/` and `evaluation_reports/` used by `src/train_models.py` and `src/inference.py`
- **Key name inconsistency:** CSV column names use CapitalCase (`Age`, `Income`, `InvestmentHorizon`, `RiskTolerance`, `ExperienceYears`); inference dict uses mixed case (`age`, `income`, `horizon`, `risk_tolerance`, `experience`). Mapping table lives in `src/inference.py:58`

## Anti-Patterns

### Stochastic Label Generation

**What happens:** `run_allocations_pipeline()` in `src/allocations.py:300` calls `np.random.choice(['Aggressive', 'Moderate', 'Conservative'], p=list(p.values()))` to assign each investor a risk profile, producing non-deterministic training labels on each pipeline run.

**Why it's wrong:** Identical investor features can map to different labels across runs, introducing irreducible label noise that prevents the Stage 1 classifier from learning a clean decision boundary — observed accuracy ceiling is ~46%.

**Do this instead:** Assign labels deterministically by taking `argmax(profile_probs)` instead of sampling. This makes labels reproducible and removes noise without changing the feature-label correlation structure.

### Duplicate Stage 4 Logic

**What happens:** `src/inference.py:86-103` replicates the ETF DataFrame preparation logic (column rename, numeric coercion, `get_category_mapping` call, split by asset class) that also exists in `allocations.run_allocations_pipeline()`.

**Why it's wrong:** If column names or imputation defaults change in `allocations.py`, the inference path must be updated separately; divergence causes silent mismatches.

**Do this instead:** Extract ETF preparation into a shared helper function in `src/allocations.py` called by both `run_allocations_pipeline()` and `src/inference.py`.

## Error Handling

**Strategy:** Fail-fast during training (exceptions propagate to `pipeline.py` which prints traceback and calls `sys.exit(1)`); silent fallback in Stage 4 ETF selection (bare `except Exception` at `src/allocations.py:234` falls back to uniform random pick).

**Patterns:**
- `pipeline.py` wraps each step in try/except and exits with code 1 on failure
- `src/inference.py:validate_input()` raises `ValueError` with descriptive message for invalid input
- `src/allocations.py:assign_portfolio_numeric_aum()` catches all exceptions per ETF pick and falls back to `np.random.choice` with uniform probability

## Cross-Cutting Concerns

**Logging:** `print()` statements throughout — no structured logging library. Training steps prefix output with step headers; no log files.

**Validation:** Shared rules in `src/validation_rules.py`; applied at batch level in `src/data_validation.py` and at request level in `src/inference.py`.

**Authentication:** No user authentication. OpenAI and Finnhub API keys loaded from `.env` via `python-dotenv`. `.env` is gitignored.
